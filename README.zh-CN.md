长篇写作最难的，往往不是写出第一段，而是让后面的情节、人物和设定继续接得上。

AI 小说生成器把这些工作放进同一个本地应用：先理清故事，再拆成卷、篇章、场景和章节；写作时随时查看人物、地点、势力、物品与世界规则。AI 可以参与构思、规划和起草，你可以修改候选内容，再决定保存什么。

**适合希望边写边调整，也希望掌握 AI 如何参与创作的你。**

> 当前 `main` 是重写后的版本。上一版代码保存在 [`old`](https://github.com/YILING0013/AI_NovelGenerator/tree/old)，仅供参考。两版的数据结构不同，升级时请备份旧数据，并为新版使用独立数据库。

截图均来自实际运行的应用，使用虚构作品《雾港来信》作为演示资料，统一按桌面 **16:10** 比例拍摄。它们展示界面与操作方式，不代表模型生成质量。界面也支持移动端适配。

## 从这里开始

你可以只用默认流程，也可以逐渐把它改成适合自己的写法。

| 你想做的事 | 从哪里开始 |
| --- | --- |
| 手上只有一个故事点子 | 新建小说，整理故事核心、主线、基调和世界观 |
| 已有大纲，想把它写细 | 卷规划 → 篇章规划 → 场景 → 章计划 |
| 人物越来越多，怕写乱 | 角色卡、势力卡、关系图谱与章后记录 |
| 想控制 AI 怎么写 | 调整任务流程、节点提示词、输入资料和模型 |
| 想直接写作，不研究流程 | 使用内置方案，在章节编辑器里起草、修改和保存 |

### 01 / 先把故事说清楚

书架集中管理作品。进入一本书后，小说信息页保存这部作品的标题、核心创意、主线剧情、简介、世界观、写作风格和预计篇幅。

这些内容可以手工填写，也可以借助 AI 创建或改写。先把“主角想要什么、阻力是什么、故事最后要走向哪里”讲清楚，后面的规划才有共同的方向。

![小说信息：故事核心、主线剧情、世界观和写作风格](.github/assets/readme/story.png)

### 02 / 用雪花式拆分，把大故事变成今天能写的一章

项目借鉴雪花写作法中“从故事核心逐步展开”的思路。内置的新建小说流程会先把点子展开为压缩故事，再提炼创意与核心种子，整理小说信息；其中核心种子节点明确使用雪花写作法的第一步。

有了全书方向，接下来沿着 **卷 → 篇章 → 场景 → 章计划 → 正文** 逐层细化。每一层都可以停下来修改。

| 层级 | 要回答的问题 | 《雾港来信》的例子 |
| --- | --- | --- |
| 故事核心 | 谁遇到了什么事，必须做什么？ | 修复师收到失踪母亲的旧信，开始追查一艘运送记忆的邮船 |
| 卷 | 这一大段故事要完成什么变化？ | 第一卷找到邮船航路，确认母亲可能仍然活着 |
| 篇章 | 哪几次冲突推动这段进展？ | 调查旧港失踪案，发现钟声与信件之间的联系 |
| 场景 | 这一段发生在哪里，人物做了什么？ | 雨夜的修复室里，一封信从门缝滑入 |
| 章计划 | 这一章要写到哪里，必须出现什么？ | 辨认笔迹、发现旧邮戳、以远处的钟声收尾 |
| 正文 | 怎样把计划写成读者能感受到的故事？ | 从停住的铜钟、雨声和温热的信纸开始写 |

![卷规划：查看各卷的目标、冲突、转折与起止状态](.github/assets/readme/volumes.png)

卷规划还可以整理本卷会用到的角色、势力和地点。篇章与场景继续承接上层目标，避免每次生成都从一张白纸开始。

### 03 / 写正文，也保留修改的余地

章节编辑器把目录、章计划、正文和章后记录放在同一处。你可以选中一章，先核对目标与情节节点，再自己写作或让 AI 起草。

- **章计划**：记录本章目标、起止状态、关键情节，以及必须写到和需要避开的内容。
- **正文**：编辑、保存、统计字数，并导出当前草稿。
- **历史版本**：查看旧稿、比较修改，需要时恢复已有版本。
- **章后记录**：检查正文涉及的人物心理、人物关系、物品持有人和世界规则，再确认需要记录的变化。

生成结果可以先看、先改，再确认。随着故事推进，已确认的记录帮助你追踪“到这一章为止，哪些事情已经发生”。

### 04 / 给人物和世界留一本随手可查的资料册

人物不只是姓名与外貌。角色卡还保存欲望、恐惧、与主线的冲突、成长方向和剧情作用；人物资料可以按故事开始、卷开始、章前或章后的位置确认与查看。

![角色管理：角色列表、人物设计与按剧情位置查看的资料](.github/assets/readme/characters.png)

| 模块 | 可以在这里整理什么 |
| --- | --- |
| 角色卡 | 人物档案、成长设计、不同剧情位置的资料，以及人物关系 |
| 势力卡 | 组织目标、公开立场、隐藏目的、资源与角色归属 |
| 地点卡 | 场所信息，以及某一卷实际使用的地点 |
| 物品卡 | 关键物品、持有人与剧情中的转交变化 |
| 设定规则卡 | 世界中什么可以发生、限制是什么、需要付出什么代价 |
| 伏笔 | 线索、相关剧情记录，以及后续的回收情况 |
| 关系图谱 | 从图上查看人物、势力及它们之间的联系 |
| 小说助手 | 围绕当前作品查找资料、讨论问题，并审核它提出的修改 |

## 把 AI 流程改成自己的写法

“生成一章”背后通常不只一次模型调用：先取得当前计划与相关资料，再整理上下文，最后生成候选正文。项目把这些步骤放在可编辑的流程画布中。

打开某项 AI 操作的任务流程，就能看到它读取什么、先做哪一步、把哪些结果交给后面的节点。内置方案覆盖新建小说、人物与势力、分卷、篇章、场景、正文和章后检查等任务。

![任务流程画布：节点库、生成步骤与数据连线](.github/assets/readme/workflow.png)

### 自定义节点，具体能改什么？

你可以添加节点、调整连线，也可以直接修改已有节点的提示词、输入输出字段和模型配置。同一个流程中的不同 AI 节点可以使用不同模型。

| 节点 | 直白一点说 |
| --- | --- |
| 开始输入 / 页面资料 | 接收本次要求，或读取当前小说与写作位置的资料 |
| 固定值 / 文本模板 | 放入固定写作要求，把上一步的内容填进提示词 |
| 组装字段 | 把几份输入整理成下一步需要的字段 |
| AI 生成 | 调用选定模型，返回文本或指定结构的内容 |
| AI 整理资料 | 在当前小说中查阅、筛选资料，交给后面的步骤 |
| 条件分支 / 合并分支 | 根据输入决定走哪条路，再汇集结果 |
| 子流程 / 逐项处理 | 复用一组步骤，或对一组内容逐项执行 |
| 任务输出 | 把最终候选交回原页面，供你审核和保存 |

这里的自定义，是使用这些节点组合自己的生成流程；复杂的资料结构仍需要理解字段与 JSON 的含义。

### 例如：让故事核心更符合你的口味

内置的“核心种子”节点会读取主线、类型、基调、目标读者和篇幅，把它们压缩成一句清楚的故事核心。你可以在提示词里强调“冲突要来自人物选择”“保留温柔的基调”，也可以给这个节点单独指定模型。

![节点提示词编辑：插入输入字段并调整雪花写作法的核心种子提示词](.github/assets/readme/node.png)

从默认方案开始修改时，可以按这个顺序来：

1. 在“方案”中复制现有流程，给自己的版本起一个名字。
2. 在节点库中添加需要的步骤，或选中已有节点进行编辑。
3. 用**数据连线**传递内容，用**执行连线**安排顺序与分支。
4. 调整提示词、输入输出字段、模型与生成参数。
5. 检查流程，保存方案，再回到原来的 AI 操作使用它。

流程还支持撤销、重做、方案修订，以及不调用模型的资料预览。预览可以帮助检查输入和连线；真实生成效果仍取决于模型与实际上下文。

## 在本机运行

应用由浏览器界面、Python 后端和 MongoDB 组成。Windows 用户可以用桌面启动器管理服务；也可以分别在终端中启动。

### 准备环境

| 依赖 | 要求 |
| --- | --- |
| Python | 3.13 或 3.14，使用对应系列的较新补丁版本 |
| Node.js 与 npm | Node.js 20.9 或以上，使用仍在维护的版本 |
| MongoDB | **副本集**；下面提供单机副本集配置 |
| Docker | 使用下面的 MongoDB 方案时需要；已有副本集可跳过 |
| 模型服务 | 需要自行准备 API Key、接口地址与模型名称 |

部分写作保存会同时更新多条记录，因此需要 MongoDB 事务。只启动普通的独立 MongoDB 实例，不能满足完整写作流程的要求。

### 1. 下载项目并安装依赖

以下命令在 PowerShell 中执行：

```powershell
git clone https://github.com/YILING0013/AI_NovelGenerator.git
cd AI_NovelGenerator
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm ci
cd ..
```

macOS / Linux 的虚拟环境解释器路径为 `.venv/bin/python`，后续可参考[手动启动](#手动启动)。

### 2. 准备 MongoDB

如果已有可用的 MongoDB 副本集，可以直接配置连接地址。使用项目附带的 Docker 配置时，先确认本机 `27017` 端口没有被其他服务占用：

```powershell
docker compose -f compose.mongodb.yaml up -d
docker compose -f compose.mongodb.yaml exec mongodb mongosh
```

在打开的 MongoDB 命令行中执行：

```javascript
rs.initiate({
  _id: "rs0",
  members: [{ _id: 0, host: "localhost:27017" }]
})
exit()
```

`rs.initiate` 只需对**新建的数据卷执行一次**。回到 PowerShell，运行 `docker compose -f compose.mongodb.yaml ps`，确认状态为 `healthy`。

首次配置时，将 `backend/config/config_default.yaml` 复制为 `backend/config/config.yaml`。已有配置文件时直接编辑，避免覆盖之前保存的模型配置。

在配置中填写：

```yaml
mongodb_url: "mongodb://127.0.0.1:27017/?replicaSet=rs0&directConnection=true"
mongo_database_name: "novel_generator"
mongo_transaction_mode: "required"
```

附带的 Docker 配置使用命名数据卷保存数据，只将端口发布到本机 `127.0.0.1`，没有配置数据库密码。修改数据库连接后需要重启后端。

### 3. 启动应用

Windows 下双击 **`start.bat`**，在桌面启动器中启动服务。启动器可以设置端口、查看日志、停止服务；生产模式会在首次运行或相关源码、配置变化后构建前端。

| 服务 | 默认地址 |
| --- | --- |
| 写作界面 | <http://127.0.0.1:3300> |
| 后端 | <http://127.0.0.1:8200> |
| API 文档 | <http://127.0.0.1:8200/docs> |

关闭启动器会停止它启动的服务。更改端口前先停止服务；如果端口已占用，先确认已有进程是否就是当前项目。

### 4. 配置模型，写出第一章

打开**设置**，填写服务商的 API Key、接口地址和模型名称，然后启用对应配置。项目包含 OpenAI、DeepSeek、Gemini、Claude 及相应兼容接口的适配；具体参数以所选适配器和服务商支持范围为准。

第一次使用，建议先做一本短篇演示：

1. 新建小说，填写点子与预计篇幅，确认小说信息。
2. 准备核心势力、角色、关系和世界规则；按左侧创作进度补齐当前步骤。
3. 规划全书分卷，展开当前卷，并确认会用到的角色、势力与地点。
4. 拆出篇章、场景和章计划，生成或手写第一章。
5. 修改并保存正文，再检查需要记录的章后变化。

默认流程已经可以作为起点，不必在第一次写作前配置所有节点。项目不附带 API Key，模型调用产生的费用由你配置的服务商收取。

### 手动启动

在项目根目录启动后端：

```powershell
.\.venv\Scripts\python.exe main.py
```

另开一个终端启动前端：

```powershell
cd frontend
npm run build
npm run start -- --hostname 127.0.0.1 --port 3300
```

如果后端地址不是默认值，在构建前设置 `NEXT_PUBLIC_API_BASE`。例如 PowerShell 中使用 `$env:NEXT_PUBLIC_API_BASE = "http://127.0.0.1:8200"`。桌面启动器会根据它管理的端口设置这个地址。

数据库连接也可以通过 `NOVEL_GENERATOR_MONGODB_URL` 和 `NOVEL_GENERATOR_MONGO_DATABASE_NAME` 环境变量覆盖。

## 数据、备份与升级

小说数据存放在你配置的 MongoDB 和本地文件中。执行 AI 操作时，相关上下文会发送给你选择的模型服务；“在本机运行”不代表模型推理也在本机完成。

| 需要备份的内容 | 存放位置 |
| --- | --- |
| 小说、人物、规划与写作记录 | MongoDB |
| 模型配置与 API Key | `backend/config/config.yaml` |
| 自定义工作流等运行数据 | `data/` |
| 封面等上传文件 | `static/` |

升级前先备份并停止服务，再更新代码、安装依赖和重新构建前端。旧版与新版请使用不同数据库；当前没有承诺能直接迁移旧版数据。

应用面向本地使用，没有供公网使用的用户认证。不要把应用服务或无密码的 MongoDB 直接暴露到互联网。提交问题时，请去掉密钥、数据库密码、个人路径和未公开的小说内容。

<details>
<summary><strong>常见问题</strong></summary>

**页面能打开，为什么保存篇章或章节失败？** 先确认 MongoDB 已初始化为副本集、能正常写入，并核对 `mongodb_url` 和 `mongo_transaction_mode`。更改配置后重启后端。

**为什么某个 AI 操作还不能开始？** 查看页面给出的前置步骤。上层规划、剧情或相关资料变动后，可能需要重新检查并确认。

**能使用自定义接口地址吗？** 可以配置地址和模型名，但接口必须支持所选适配器需要的请求格式；不同模型支持的输出方式和参数可能不同。

**支持手机、深色模式或英文吗？** 支持移动端适配、明暗主题和中英文切换。本文集中展示桌面写作界面。

**旧版去哪里了？** 在 [`old` 分支](https://github.com/YILING0013/AI_NovelGenerator/tree/old)。旧版 Issue 和 PR 已在版本切换时统一关闭，这不表示每个历史问题都已单独修复。

</details>
